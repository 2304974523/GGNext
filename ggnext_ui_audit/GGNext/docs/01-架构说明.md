# 架构说明

## 1. 分层

```
┌─────────────────────────────────────────────┐
│  ui/            表现层（Compose）            │
│  ├ PanelScreen  面板骨架                     │
│  ├ screen/      4 个页签                     │
│  ├ sheet/       22 个弹窗                    │
│  ├ components/  通用组件                     │
│  ├ home/        主页                         │
│  └ theme/       主题 / 动效 / 尺寸           │
├─────────────────────────────────────────────┤
│  core/Session   状态层（单例 + StateFlow）   │
├─────────────────────────────────────────────┤
│  engine/        领域层（纯 Kotlin，可单测）  │
│  ├ NumberParser 输入语法解析                 │
│  ├ Formatter    显示格式                     │
│  ├ MemoryEngine 内存读写与检索               │
│  └ Shell        su 通道                      │
├─────────────────────────────────────────────┤
│  data/          数据层                       │
│  ├ Settings     DataStore 持久化             │
│  ├ ProcessScanner  /proc 与 PackageManager   │
│  ├ SearchHistory 输入历史                    │
│  └ AppLog       日志缓冲                     │
└─────────────────────────────────────────────┘
```

依赖方向单向向下：ui → core → engine/data。engine 不依赖 Android UI，可脱离设备做单元测试。

## 2. 状态管理

### 2.1 单一状态源

`core/Session.kt` 是一个 `object` 单例，持有：

- `MutableStateFlow<Ui>` —— 全部界面状态
- `MemoryEngine` 实例 —— 全部内存操作
- `SettingsRepository` —— DataStore 读写
- `CoroutineScope(SupervisorJob + Dispatchers.Main.immediate)` —— 全局协程作用域

这样设计的原因：**Compose 面板需要同时被 Activity 和 Service（悬浮窗）渲染**。
如果状态挂在 ViewModel 上，两个宿主会各持一份，附加进程/搜索结果无法同步。

### 2.2 状态结构

```kotlin
data class Ui(
    val tab: NextTab,                    // 当前页签
    val results: List<MemoryItem>,       // 搜索结果
    val saved: List<MemoryItem>,         // 已保存
    val memoryRows: List<MemoryItem>,    // 内存编辑器行
    val target: TargetProcess?,          // 已附加进程
    val regions: List<RegionRow>,        // 15 个内存区域统计
    val selectedRegions: Set<String>,    // 已勾选区域
    val sheet: Sheet,                    // 当前弹窗
    val search: SearchInput,             // 搜索面板输入状态
    val settings: Map<String, String>,   // 全部设置项
    val metrics: UiMetrics,              // 字体缩放 / 圆角等
    val preset: ThemePreset,             // 主题预设
    val darkMode: DarkMode,              // 深浅模式
    val tools: Map<NextTab, List<ToolId>>, // 各页工具栏顺序
    // ...
)
```

### 2.3 状态变更范式

所有变更都通过 `_ui.update { it.copy(...) }`，没有可变字段：

```kotlin
fun toggle(item: MemoryItem) {
    mutate { if (it.address == item.address) it.copy(checked = !it.checked) else it }
    recount()
}
```

好处：Compose 侧只需 `collectAsStateWithLifecycle()`，配合 `LazyColumn` 的稳定 key，
列表项只在真正变化时重组。

## 3. 内存引擎

### 3.1 附加与降级

```kotlin
engine.attach(pid, is64)
  ├─ 读取 /proc/<pid>/maps → 解析成 MemoryRegion 列表
  └─ 尝试打开 /proc/<pid>/mem（随机访问）
       ├─ 成功 → simulated = false（真实读写）
       └─ 失败 → simulated = true（沙盒模拟，界面功能完整可用）
```

`simulated` 会显示在设置页底部，避免用户误判。

### 3.2 检索流程

```
输入字符串
  → NumberParser.parse()           识别 文本/范围/联合/异或/普通数字
  → MemoryEngine.Criteria          构造检索条件
  → engine.search(criteria, prev)  分块扫描（64KB buffer）
      ├─ prev == null → 按值与符号匹配
      └─ prev != null → 改善模式，用 address→value 的 Map 做 O(1) 比对
  → List<MemoryItem>
```

分块扫描的要点：
- 每块 64 KB，避免为每个地址做一次 `seek`
- Byte 类型步长 1，其余按类型宽度对齐
- 区域过滤：可读可写、在指定地址范围内、非系统库（可配置）

### 3.3 格式化与缓存

`Formatter` 有 14 位显示掩码，逐位控制显示哪些格式：

| 位 | 含义 | 位 | 含义 |
|---|---|---|---|
| 0 | HEX | 7 | Dword |
| 1 | 逆序 HEX | 8 | Float |
| 2 | 字符串 | 9 | Double |
| 3 | Java 字符串 | 10 | Word |
| 4 | ARM x32 | 11 | Byte |
| 5 | Thumb | 12 | Qword |
| 6 | ARM x64 | 13 | Xor |

`render()` 带 512 项 LRU 缓存，键为 `(value, flags, mask)`，滚动时不重复计算。

## 4. 悬浮窗

### 4.1 结构

```
FloatingIconService (前台服务)
  ├─ 悬浮球：HotIconView（自绘圆形 + 进度环）
  │    拖动与点击在同一个 OnTouchListener 内判定
  │    位移 < 8dp 且按下 < 320ms → 视为点击
  └─ 面板：ComposePanel 挂到 WindowManager
       ComposeView 需要三个 owner 才能工作：
         LifecycleOwner / ViewModelStoreOwner / SavedStateRegistryOwner
```

### 4.2 三个 owner 的必要性

`collectAsStateWithLifecycle()` 内部会查找 `LocalLifecycleOwner`。
在 Activity 里它由 `ComponentActivity` 提供，但在 Service 的裸窗口里没有，
不补齐会直接抛异常（表现为窗口一片空白）。

`ComposePanel` 的实现：

```kotlin
class ComposePanel(...) : LifecycleOwner, ViewModelStoreOwner, SavedStateRegistryOwner {
    fun attach(parent: ViewGroup) {
        savedStateController.performRestore(null)
        lifecycleRegistry.currentState = Lifecycle.State.CREATED
        val cv = ComposeView(context).apply {
            setViewTreeLifecycleOwner(this@ComposePanel)
            setViewTreeViewModelStoreOwner(this@ComposePanel)
            setViewTreeSavedStateRegistryOwner(this@ComposePanel)
            setContent { PanelContent() }
        }
        parent.addView(cv, ...)
        lifecycleRegistry.currentState = Lifecycle.State.RESUMED
    }
}
```

## 5. 主题与动效

### 5.1 主题

`ui/theme/DynamicTheme.kt`：

- `ThemePreset` 8 个枚举，每个带一个 seed 色
- `DarkMode` 三态
- `rememberScheme()` 优先使用 Android 12+ 的 `dynamicDark/LightColorScheme`，
  否则用 `presetScheme(preset, dark)` 派生完整的 M3 ColorScheme

### 5.2 尺寸缩放

`LocalUiMetrics` 提供 `fontScale` / `dialogCorner`，所有字号都通过 `fsp()` 换算：

```kotlin
@Composable
fun fsp(base: Float) = (base * LocalUiMetrics.current.fontScale).sp
```

改设置里的滑块 → 写 DataStore → `Session.ui.metrics` 更新 → 全局立刻重绘。

### 5.3 动效

`ui/theme/Theme.kt` 的 `Motion` 对象集中定义，按类型分开：

```kotlin
object Motion {
    val Fast: TweenSpec<Float>       // 140ms
    val Normal: TweenSpec<Float>     // 240ms
    val Springy: SpringSpec<Float>
    val ColorFast: TweenSpec<Color>  // 颜色单独一套，避免跨类型装箱
    val ColorNormal: TweenSpec<Color>
}
```

性能约定：入场/按压动画只写 `graphicsLayer`（alpha / translationY / scale），
不触发布局，也不触发重组。

## 6. 性能要点

| 措施 | 位置 |
|---|---|
| `LazyColumn` + 稳定 key + contentType | 三个列表页 |
| 行内派生值 `remember` | 列表行 |
| 格式化 LRU(512) | `Formatter.render` |
| 动画只写 graphicsLayer | `ItemEnter`、按压反馈 |
| 输入框局部 `TextFieldValue` | 搜索面板、编辑面板 |
| 图标 LRU(48) + 96px 预缩放 | `AppIconCache` |
| 首屏入场动画只给前 14 项做延迟阶梯 | `ItemEnter` |
| 内存行预分组（`chunked(4)` 在 `remember` 里） | `MemoryScreen` |
