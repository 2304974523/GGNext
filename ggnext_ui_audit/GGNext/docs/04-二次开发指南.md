# 二次开发指南

本文给出最常见的扩展场景，照着改即可。

## 1. 增加一种数据类型

假设要加 `Int16`（其实等于 Word，仅作示例）。

**Step 1** `model/ValueType.kt`

```kotlin
const val INT16 = 128            // 用未被占用的位
fun sizeOf(flags: Int) = when (flags and 0xFF) {
    INT16 -> 2
    // ...
}
```

**Step 2** `engine/NumberParser.kt`

在 `parseNumber()` 的 `when (targetType and 0xFF)` 里加分支。

**Step 3** `engine/Formatter.kt`

在 `items` 列表加一项（`FormatItem(bit, short, label)`），
并在 `render()` 里加对应的输出分支。

**Step 4** `engine/MemoryEngine.kt`

`matches()` 与 `readValue()` 无需改动，只要 `sizeOf` 正确即可。

## 4. 接入真正的冻结循环

当前 `MemoryItem.freeze` 只有 UI 与模型，没有定时写回。补齐方式：

```kotlin
// core/Session.kt
private var freezeJob: Job? = null

fun startFreezeLoop(intervalMs: Long = 100) {
    freezeJob?.cancel()
    freezeJob = scope.launch {
        while (isActive) {
            _ui.value.saved.filter { it.freeze }.forEach { item ->
                engine.write(item.address, item.size, item.value)
            }
            delay(intervalMs)
        }
    }
}

fun stopFreezeLoop() {
    freezeJob?.cancel()
    freezeJob = null
}
```

在 `attach()` 成功后调用 `startFreezeLoop()`，
在 `toggleFreeze()` 与离开页面时按需启停。

## 5. 接入 Capstone 反汇编

`Formatter` 已预留 `F_ARM` / `F_THUMB` / `F_ARM64` 三个掩码位。

**Step 1** 放 `libcapstone.so` 到 `app/src/main/jniLibs/<abi>/`

**Step 2** 写 JNI 桥

```kotlin
object Disasm {
    external fun disasm(bytes: ByteArray, mode: Int, count: Int): Array<String>

    init { System.loadLibrary("capstone-bridge") }
}
```

**Step 3** 在 `Formatter.render()` 里

```kotlin
if (mask and F_ARM != 0) {
    val bytes = ByteArray(size) { i -> ((item.value ushr (i * 8)) and 0xFF).toByte() }
    Disasm.disasm(bytes, MODE_ARM, 1).forEach { sb.append(it).append("; ") }
}
```

## 6. 替换模拟引擎

`MemoryEngine.simulate()` 目前生成演示数据。若想接入其他后端
（例如自研守护进程、WebSocket 远程调试），替换这两个入口即可：

```kotlin
// 检索
fun search(criteria: Criteria, previous: List<MemoryItem>?): Result

// 读写
fun read(address: Long, size: Int): Long?
fun write(address: Long, size: Int, value: Long): Boolean
```

其余代码只依赖这三个方法，不需要改动 UI。

## 9. 修改输入语法

`engine/NumberParser.parse()` 是唯一入口，返回 `Query`：

```kotlin
data class Query(
    val kind: Kind,          // NUMBER / TEXT / RANGE / GROUP
    val numbers: LongArray,
    val types: IntArray,
    val to: LongArray,       // 范围上界
    val sign: Int,           // 比较符号
    val xorKey: Int,
    val area: Int,           // 联合搜索区域
    val ordered: Boolean,
    val textBytes: ByteArray?
)
```

加新语法只需在 `parse()` 顶部识别并构造对应的 `Query`，
引擎侧 `MemoryEngine.search()` 会按 `kind` 分流。

## 10. 调试技巧

```kotlin
// 全局日志（可在设置页「日志」查看）
AppLog.add("TAG", "message")

// 界面提示
Session.toast("提示")
```

日志走 `Session`/`AppLog` 的环形缓冲（500 条），不会污染 logcat，
需要抓 logcat 时用 `android.util.Log` 即可。

内存引擎在模拟模式下会打印：

```
[attach] pid=xxxx x64=true regions=42 root=false
[search] type=4 value=100 found=480 scanned=0 regions=0
```
